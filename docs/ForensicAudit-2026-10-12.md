# Pawtrackr forensic audit and verification

The groomer chooses the checkout amount. New checkouts now start with an empty amount, and service or add-on selection never fills, replaces, or supplies a fallback price. Explicitly selected loyalty rewards retain their existing visible credit rules. The entered amount survives service changes, navigation, and draft recovery. The bilingual on-screen hint now asks for the groomer's chosen amount. Legacy catalog price fields remain available for store compatibility and historical receipt breakdowns.

This audit follows the repository architecture memory where the attached charters conflict: persistence is local, subscriptions remain paused, receipt workflows are digital, aggression clearance includes calm/cooperative/anxious/nervous observations, and special needs remains a separate purple priority-care flag. Pet removal retains the existing archive/restore behavior; it does not become a destructive delete.

## Limits and remaining evidence

The requested absolute claims—zero bugs, zero leaks, zero frame hitches, and exhaustive verification of every workflow—are not established by these results.

- Strict concurrency was explicitly compiled with `SWIFT_STRICT_CONCURRENCY=complete`. The project still uses Swift 5 language mode and emits existing diagnostics, including model/key-path Sendable issues, actor-isolated XCTest setup/teardown, and UI helper isolation. There is no clean Swift 6 certification. The baseline log contains 1,294 emitted warning lines, including repeated diagnostics; this is not a count of unique defects.
- Both complete result bundles report a priority-inversion runtime warning associated with StoreFileLockCoordinatorTests. The final compact-screen checkout run also emitted an invalid-frame warning during amount-field interaction. Passing assertions do not establish warning-free runtime behavior.
- Some existing persistence paths still save on MainActor, including ServiceRepository, emergency-contact editing, and attention outreach. They remain architectural work under Pawtrackr/AGENTS.md; this patch does not claim that every database operation is off the UI executor.
- The 100-cycle test proves view-model release in a disposable container. It is not 100 actual UI push/pop cycles with Instruments/memgraph heap-baseline evidence.
- No ETTrace, GPU/frame-time capture, or measured 8.3 ms ProMotion rendering certification was performed. Functional/latency tests do not establish zero dropped frames.
- Historical store fixtures pass, but installing a prior signed App Store build and upgrading it in place on physical hardware remains a release check.
- POSIX locking tests establish descriptor exclusion, stable lock-file inode, timeout, and nesting for launch-time store-file operations. The file lock does not protect an already-open SQLite container; the source explicitly documents this distinction.
- The attachments' ClientListStressTests and ClientListChaosTests are absent. Actual stress coverage is the existing repository tests plus the implemented ConcurrencyHardeningTests and ConcurrencyStressHarness.

No user records were edited or deleted by the audit. UI mutations ran against disposable test data. Native UI inspection was read-only except selecting the Clients surface and inspecting its sort menu. No commit, push, release, subscription activation, cloud persistence, or peripheral integration was performed.
